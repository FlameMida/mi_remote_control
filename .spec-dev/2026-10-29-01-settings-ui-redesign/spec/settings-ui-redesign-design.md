# MiRemote 全窗体 UI 重设计 设计

## 背景与目标

MiRemote 的界面由三类窗体组成：主设置窗（4 个侧栏页和若干 sheet / 对话框）、首次引导，以及屏幕浮层和菜单栏面板。它们各自演进，现在有 4 个问题：
1. 视觉层级、间距、状态色不统一。
2. 编辑器允许改动引擎会忽略的槽位（见「约束归属」），用户保存后不生效。
3. 「未连接 / 缺权限 / 通道故障」只在部分窗体中露出。
4. 不支持 macOS 26 的液态玻璃外观，侧栏也不能收起。

本次在**不改信息架构、不改术语、不改行为**的前提下，重画全部窗体。

**成功标准**：
1. 范围清单中的每一个窗体（见「窗体清单」）都有新设计稿、浅色 / 深色截图和对应的验收行。
2. 侧栏仍为 4 页：按键映射 / 场景配置 / 语音 / 通用。模式与功能名称与现有代码完全一致。
3. 基础状态下由引擎处理的短按槽位（方向键、返回键、全局 OK）在槽位下方显示一行纯文字说明，讲清这里的设置何时生效，避免「保存成功但没效果」的困惑；槽位外观与可编辑性和原 UI 一致。
4. 侧栏可通过标题栏按钮和 ⌃⌘S 收起或展开。
5. 在 macOS 26 上，侧栏、工具栏、浮层、菜单栏面板使用液态玻璃。在 macOS 14–15 上，或开启「降低透明度」时，自动回退到不透明材质，信息与布局一致。
6. 浅色 / 深色以及最小窗口下都没有截断和重叠。`config.json` 格式不变，现有映射行为不变。

## 非目标

- 不合并页面：「场景配置」仍是独立的侧栏页，只在原位重画（用户决定 2）。
- 不新增页面：不加「概览」页。状态改进只放进已有界面，即侧栏头、页内横幅和体检 sheet；菜单栏面板保持原条目（用户决定 3）。
- 不改术语和结构：保留「快捷控制模式 / App 控制模式 / App 导航模式」和「第二功能模式（高级）」折叠区（用户决定 4）。
- 不改默认场景行为（用户决定 5，见「默认场景行为（现状，保持不变）」）。
- 不改按键引擎、手势时序、层语义、基础层保护规则、浮层的触发键与 HintBar 键位，也不改 `config.json` 结构与版本。
- 不引入第三方依赖（零依赖 Swift 6 / SwiftUI，macOS 14+）。液态玻璃只用系统 API。
- **不可接受的结果**：重设计后任何既有映射或浮层行为发生变化，或者用户在新 UI 里能「成功保存」一个引擎不会执行的绑定。

## 术语表（沿用现有代码文案，不改名）

- **全局默认 / 按 App 覆盖**：场景（代码中为 `profile`）。「全局默认」是所有 App 的起点。按 App 覆盖只改需要不同的键，其余继承全局。
- **第二功能模式（高级）**：映射页检查器中的折叠区，标题和说明文字沿用现有代码。区内三行分别是：
  - **快捷控制模式**（层 1，按住 OK）
  - **App 控制模式**（层 2，单击 TV 进出）
  - **App 导航模式**（层 3）
  - 显示名取自 `AppModel.modeDisplayName`。
- **触发方式**：短按 / 长按 / 双击（沿用现有文案「短按」）。
- **来源标签**：「App 覆盖」「继承全局」，是新增的展示样式，不是新术语。
- **基础状态短按说明**：不是标签、不带图标，也不锁定槽位，只是一行次要文字。依据为 `MappingEngine.fireTap` 536–545 行在基础状态（layer 0）下的处理，以及 `GeneralPage.swift:102` 的现有说明「基础状态为文字输入：方向、确认、删除固定保持原生语义；App 快捷动作仅在第二功能、导航模式或明确组合手势中生效。」：
  - 方向键短按 = 光标键
  - 返回短按 = Delete
  - OK 短按 = Return；只有 App 场景（per-app profile）明确设置的短按会替代它，全局默认改不动
  - 进入第二功能模式后，若该模式没有单独设置，会回落到这里的短按设置
- **液态玻璃（Liquid Glass）**：macOS 26 的半透明折射材质，SwiftUI 中为 `glassEffect`。
- **回退材质**：macOS 14–15 上，或「降低透明度」开启时使用的 `.regularMaterial` / 不透明窗口背景。

## 参与者与适用行为

- **普通用户**：查看和修改映射、管理场景、处理「按了没反应」。
- **重度用户**：维护多个 App 场景与 App 控制模式（AI 批准流），常开着设置窗，需要收起侧栏换取空间。
- **辅助技术用户**：用键盘 / VoiceOver 操作，可能开启「降低透明度」或「增强对比度」。
- **系统（自主触发）**：连接、权限、通道状态与前台 App 变化时，刷新侧栏头、横幅、菜单栏图标与面板、浮层角标。

## 影响面

- **视觉层**：上表全部窗体。`DesignSystem.swift` 新增两部分：
  - `GlassSurface` 修饰器：macOS 26 用 `glassEffect`，否则用 material 回退；同时读取 `accessibilityReduceTransparency`。
  - 来源标签样式。
- **结构层**：`RootView` 改为 `NavigationSplitView`，或保留现结构，加上 `columnVisibility` 切换与 ⌃⌘S 菜单命令。侧栏仍为 4 项。
- **只读依赖**：`AppModel`、`MappingEngine`。需要抽出一个纯函数 `BaseTapNote` 描述基础状态下哪些短按由引擎处理，供 UI 文案使用，并与引擎对拍。
- **不影响**：BLE / HID / 音频链路、浮层触发与键位、配置格式、默认场景逻辑。

## 已确认的关键决策（来源：用户回答，2026-10-29）

1. **范围 = 所有窗体都要改**：设置页、sheet / 对话框、首次引导、菜单栏面板、全部浮层。
2. **不合并**：「场景配置」保持独立的侧栏页，原位重设计。映射页的场景标签只负责「跳到场景配置」，不提供页内切换。
3. **不新增**：没有「概览」页，侧栏仍是 4 项。状态改进放进侧栏头的问题行、各页横幅和体检 sheet（菜单栏面板保持原条目）。
4. **保留原有术语和结构**：「快捷控制模式 / App 控制模式 / App 导航模式」「第二功能模式（高级）」折叠区、「短按 / 长按 / 双击」、「全局默认 / 按 App 覆盖」都不改。
5. **默认场景按目前行为，不做变更**（详见下节）。
6. **追加要求：侧栏可收起**。标题栏有切换按钮，快捷键 ⌃⌘S，收起形态遵循 macOS `NavigationSplitView` 惯例。
7. **追加要求：支持 macOS 26 液态玻璃**。范围是侧栏、工具栏、浮层、菜单栏面板，并为旧系统和「降低透明度」提供回退。
- 已有项目约束：视觉延续 `mockups/v3-macos.html` 的 macOS 系统设置风格。遥控器一律使用用户指定的画法（`REMOTE_SVG` / `RemoteDiagram`：`.rsvgwrap` / `.rshell` / `.remote-key`），所有出现遥控器的窗体都不另画，包括映射页、识别按键、配对引导第 3 步、映射速查浮层。

## 默认场景行为（现状，保持不变）

基于源码只读分析：
- **启动时**：`AppModel.currentProfile` 初始化为 `"global"`（`AppModel.swift:224`），不持久化。每次启动 App，「正在编辑」的场景都是**全局默认**。
- **进程内保留**：`AppModel` 每个进程只创建一次（`GUIAppDelegate.swift:37`）。关闭再打开设置窗，保留上次选中的场景，退出 App 后才回到全局默认。
- **只有以下 4 处会改变它**：
  - 场景详情里点「编辑映射」，切到该场景并跳到「按键映射」页（`ProfilePage.swift:78`）。
  - 「从运行中的 App 添加」，切到新场景，但**不跳页**（`ProfilePage.swift:214`）。
  - 删除当前正在编辑的场景后，回到全局默认（`ProfilePage.swift:125`）。
  - 导入 JSON 后，回到全局默认（`ProfilePage.swift:159`）。
- **从不使用前台 App 自动选择场景**。前台 App 只影响运行时生效的映射，不影响设置窗正在编辑哪个场景。
- **新设计如何呈现，不改逻辑**：
  - 映射页标题下有一个场景标签（如「Ghostty · 覆盖 10 项 · 其余继承全局」）。标签上的「在场景配置中切换 ›」只跳到「场景配置」页。
  - 场景配置列表中，正在编辑的场景显示「正在编辑」标签，前台 App 显示「前台」标签。
  - 副标题沿用原文案：「点击左侧遥控器上的按键…」，或「正在编辑场景「X」的覆盖绑定。」。

## MODIFIED Requirements

### Requirement: 设置窗外壳（侧栏 4 页 + 侧栏头状态）（改：原侧栏头只显示电量）

设置窗 SHALL 保持 4 个侧栏项：按键映射 / 场景配置 / 语音 / 通用，顺序与图标沿用现状。侧栏头 SHALL 显示遥控器名称、连接状态与电量（固定三行布局，见「侧栏头固定三行」）。当存在「缺输入监控 / 辅助功能权限」「按键通道异常」「遥控器未连接」之一时，侧栏头下方 SHALL 出现一行问题提示，点击可直达修复入口，分别是体检 sheet 或配对引导。优先级：通道故障 > 缺权限 > 未连接。

#### Scenario: 侧栏仍为 4 项
- **GIVEN** 任意状态
- **WHEN** 打开设置窗
- **THEN** 侧栏只有「按键映射、场景配置、语音、通用」4 项，没有「概览」

#### Scenario: 缺权限时侧栏出现问题行
- **GIVEN** 输入监控未授权
- **WHEN** 打开设置窗
- **THEN** 侧栏头下出现「缺少输入监控权限 · 修复」（左侧为线条警示图标，非 emoji），点击打开「一键体检与修复」sheet

### Requirement: 按键映射页（改：视觉与来源标签；结构不变）

映射页 SHALL 沿用现有结构：标题 + 原副标题文案 + 「已保存」+「识别按键」，左侧遥控器示意图（用户指定的 `REMOTE_SVG` 画法），右侧键检查器。检查器分组与原版一致：「触发方式」（短按 / 长按 / 双击）；「手势（按住 OK + 方向键）」组只在选中 OK 且当前方案的 OK 已绑定手势时出现（见 ADDED「OK 手势组按需显示」）；「第二功能模式（高级）」折叠区，折叠区内为原说明文字 + 3 行原模式名。未设置的槽位显示「无」。新增的展示内容只有以下几项：
- 13 键标注（显示当前短按动作）
- 来源标签（App 覆盖 / 继承全局）
- 方向键、返回键、OK 的短按槽位下方的基础状态说明文字（见 ADDED）
- 场景标签：只读，带「在场景配置中切换 ›」跳转
- 示意图上方的「示意图显示」分段（短按 / 快捷控制 / App 控制 / App 导航）：只改变标注显示哪一层，不改变编辑对象

#### Scenario: App 场景中继承与覆盖并存

### Requirement: 电量图标连续填充（重设计改动）

重设计 SHALL 把侧栏头的电池改为连续填充：内芯宽度 = 电量百分比（如 82% 填满 82%），外形按 SF Symbol battery 的比例（圆角机身 + 正极帽），描边和内芯跟随文字颜色（`.secondary`）。电量 ≤15% 时内芯 SHALL 改为系统红（`Color.red`），作为轻提示；阈值与菜单栏电量环一致（`StatusItemController.swift:298` 为 `percent <= 15`）。电量未知时 SHALL 保持原行为：未连接显示空描边（`.tertiary`）加「电量待连接」，已连接则显示「正在读取电量…」。文字「n%」与原版相同。菜单栏状态卡的电量环（`BatteryRingView`，`StatusItemController.swift:290-307`）本来就按百分比连续绘制，保持不变。

实现提示（不属于本 spec 的实施计划）：SF Symbol 的 battery 只有 5 档，无法连续显示，所以改用一个自定义 SwiftUI 视图：`RoundedRectangle` 描边做机身，右侧小圆角矩形做正极帽，内部填充 `RoundedRectangle`，宽度 = 内宽 × pct / 100（`GeometryReader` 或固定尺寸），尺寸跟随 `.caption2` 字号（`@ScaledMetric`），并给出 `accessibilityLabel("电量 n%")`。

### Requirement: 侧栏头固定三行，电量固定在第 3 行（重设计改动，无跳变）

原版侧栏头是两行：「遥控器控制台」加一行 caption2，「MI RC 2 Pro」与电量挤在同一个 `HStack` 里（`RootView.swift:49-63`），设备名过长或进入「正在读取电量…」时电量会被挤到下一行，头部高度随之跳变。

重设计 SHALL 让侧栏头固定为三行，三行均为固定行高（原型：18 / 14 / 14 px，头部总高 62 px）：
1. 第 1 行：「遥控器控制台」，不换行，超长省略
2. 第 2 行：设备名（`model.deviceName`，回退值按型号：RC 2 Pro 为「MI RC 2 Pro」，其他为「MI RC」，见「MI RC 2 Pro 专用遥控器示意图」），单行，超长尾部省略并以 tooltip（`.help`）给出全名

各状态（已连接显示百分比、读取中、未连接 / 未知、低电量、长设备名、窄窗口、侧栏问题行出现与否、浅色 / 深色）之间 SHALL 只有第 3 行的内容变化：头部高度、三行位置与文字左缘都不变，电量不会移到其他行。

**交互契约**（与 `REMOTE_SVG` 完全一致）：同一 180 x 480 画框与 viewBox；同 13 个 `data-key`（power / voice / up / down / left / right / ok / back / home / menu / volUp / volDown / tv），均可点击命中；选中、悬停、按下、识别中（脉冲）四种状态；映射页引线锚点按专用坐标；浅色 / 深色主题；所有使用尺寸（映射页 1.0、窄窗 0.86、引导第 3 步 0.4667、识别按键 0.42）。浮层（ov-*）原版与原型都不绘制遥控器示意图，无需切换。实施时 `RemoteDiagram.swift` 新增一套专用绘制（仍为代码绘制的矢量 `Path` / `Shape`，不用位图），与通用绘制共享按键 id、命中区与状态样式。

- **WHEN** 遥控器连上
- **THEN** 继续使用现有通用示意图 `REMOTE_SVG`，设备名回退为「MI RC」（截图 45、47）

- **WHEN** 遥控器断开（或重新连上）

### Requirement: 短标签不断行与标题区排版（视觉刷新）

所有页面标题区、工具栏、行、标签、徽标、按钮、分段与 sheet 中的短标签 SHALL 不在词中断行（如「已保存」「识别按键」「电量 82%」）。页面标题区 SHALL 让副标题占满整行宽度：「已保存」提示放在标题同一行，副标题单独一行，不被右侧按钮挤压，避免只剩 1–2 个字落到下一行。换行的文字 SHALL 与该文字列的起始左缘对齐，不对齐到前面的圆点或图标下方。侧栏头与菜单栏状态卡中，设备名过长时侧栏截断并给出完整名提示、面板内换行，电量作为一个整体换行。窗口宽度不足时 SHALL 自动进入窄窗布局。

#### Scenario: 窄窗口下的映射页标题
- **GIVEN** 设置窗为窄窗（原型 `width=narrow` 或视口 < 1140）
- **WHEN** 映射页渲染
- **THEN** 「按键映射」「已保存」与「识别按键」在同一行且都不换行；副标题完整显示在下一行，不出现孤字

### Requirement: 无障碍与主题

所有控件 SHALL 可用 Tab / 方向键到达，并有 VoiceOver 标签。遥控器标注读作「<键名>，<触发方式或模式>，<动作>，<来源>」。浅色与深色下正文对比度 SHALL ≥ 4.5:1。「减少动态效果」开启时 SHALL 关闭弹簧与脉冲动画，配对引导的脉冲改为静态高亮。

#### Scenario: 仅用键盘编辑一个键
- **GIVEN** 焦点在侧栏
- **WHEN** 用户 Tab 到遥控器图，用方向键选到 OK，回车打开长按槽位的动作选择
- **THEN** 不用鼠标即可完成选择并保存

### Requirement: 深色模式下滚动条与滑块跟随主题

所有滚动区域（侧栏、内容区、sheet、列表、选择器、弹出面板）的滚动条与所有滑块 SHALL 跟随当前外观：深色模式下滚动条轨道透明、滑块为半透明浅色（原型：rgba(255,255,255,.3)，悬停 .45），浅色模式下为半透明深色；滑块轨道在深色模式下为深色。实施时 SwiftUI / AppKit 的 `NSScroller`（overlay 样式）与 `Slider` 默认就跟随外观，只要求不在滚动视图背后硬编码浅色背景、不强制 `.preferredColorScheme(.light)` 或固定 `NSAppearance`。原型通过按主题设置 `color-scheme` 与 `::-webkit-scrollbar` 样式模拟。

#### Scenario: 深色模式下滚动页面

- **WHEN** 用户向下滚动

### Requirement: 默认场景行为保持不变（回归保护）

重设计 SHALL NOT 改变「正在编辑的场景」的初始值与变更点（见「默认场景行为（现状，保持不变）」）。新增的场景标签、「正在编辑」「前台」标签只用于展示。

### 组件与接口（只定义边界，不写实现计划）

| 组件 | 职责 | 消费方 |
|---|---|---|
| `GlassSurface(kind: .sidebar/.toolbar/.sheet/.panel/.overlay/.chip)` | 唯一判断 macOS 26 / 14–15 / 降低透明度，输出玻璃、材质或不透明背景 | 全部窗体 |

### 错误与边界

错误处理逻辑沿用现状（本次不新增错误分支），只统一呈现方式：
- 已有的失败、警告信息（体检失败项、BlackHole 未安装、缺权限、未连接）统一用 `StatusBanner` 或带「修复」的行内提示。
- 浮层没有内容时沿用现有处理，只换外观。
- App 图标取不到时，退回首字母圆形占位（纯展示）。

## 风险

- **玻璃在花哨壁纸上可读性下降**：内容区保持高不透明度；浮层用 `.regular` 而不是 `.clear` 玻璃；以降低透明度截图为底线。
- **macOS 14 上没有 `glassEffect` API**：全部经 `GlassSurface` 加 `if #available(macOS 26, *)`，CI 用 14 SDK 下限编译。
- **规则漂移**：`BaseTapNote` 与 `fireTap` 不同源时说明文字会与实际行为不符，所以用 selfCheck 对拍。
- **改动面广**：按「设置窗 → sheet → 引导 → 菜单栏 → 浮层」切片，每片可以单独发布。
- **⌃⌘S 冲突**：系统与常见 App 的「显示边栏」都用 ⌃⌘S，与 MiRemote 自己的全局快捷键不冲突。只有设置窗为 key window 时才生效。
