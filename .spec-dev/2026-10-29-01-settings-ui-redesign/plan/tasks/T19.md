### 任务 19：final 完整验证（F）

**交付与验证**：在 T01–T18 全部实施提交之上真实运行项目完整验证（构建 + 全部 selfCheck），保存 final 回执；至少一次在 Xcode 26（Swift 6.2）SDK 下构建，使液态玻璃分支被编译（D4）。F 先于独立审查与验收，不依赖 T20、T21。

**覆盖**：全部 Requirement 的自动化部分（`--self-test` 汇总的 11 个新增 selfCheck 与既有断言）；spec「风险」第 2 条（旧 SDK 可编译）与 D4（新 SDK 编入玻璃分支）。

**文件**：
- 不修改业务文件；只写 `plan/progress.yaml`（状态）与 `execution/`（回执原件，不进 Git，由 T21 转存）。

**接口**：
- 消费：T01–T18 在 progress 中的 completed 记录与各自实施 SHA；T00 notes 中的实施路径、来源根、来源分支与基线 SHA。
- 产出：`progress.tasks.T19 = { status: completed, commit: <受测提交>, tests: pass, evidence_paths: [<final record 路径>] }`，供 T20、T21 消费。

**写入前置**：主线程执行，不做 implementer 绑定；先确认 `git status --porcelain` 为空、`progress.current` 为 null 或 T19。

**步骤 1：核对实施出口并保存 in_progress**

- 读 `plan/progress.yaml`：T00–T18 均为 completed 且各有 `commit`；任一不是 completed 则停止，不进入 F。
- 待验版本 = 实施 worktree 当前 HEAD（`git rev-parse HEAD`），应包含 T01–T18 全部实施 SHA（逐个 `git merge-base --is-ancestor <SHA> HEAD`）。
- 用临时文件 + rename 写 `T19.status = in_progress`、`current = T19`，`git add -- .spec-dev/2026-10-29-01-settings-ui-redesign/plan/progress.yaml && git commit -m "chore(T19): 开始 final 验证"`。
- 人工检查项（截图对照、实机）不在 F 内执行，留给 T20；F 只记 manual-pending。

**步骤 2：真实运行完整套件并保存回执**

在实施 worktree 根执行（`<实施路径>` 取 T00 notes，本稿生成环境为 `/workspace/mi_remote_control/.worktrees/plan/2026-10-29-01-settings-ui-redesign`）：

```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/execution-evidence.mjs" record \
  --feature "<实施路径>/.spec-dev/2026-10-29-01-settings-ui-redesign" --task T19 --phase final --attempt final-1 \
  -- bash -c "./build.sh && .build/miremote --self-test"
```

- 工具 exit 0 只表示回执已保存；读取输出 JSON 的 `exit_code` 与回执中的 stdout：须为 0，且 stdout 末行为 `SELF-TEST PASS`。编译失败、`SELF-TEST FAIL (n)`、信号中断、零输出都不记 pass。
- 记录本次构建所用工具链：`xcrun swiftc --version` 原样写入 notes。
- D4：若本次工具链低于 Swift 6.2，另在装有 Xcode 26 的机器上以同一提交、同一命令再记一次（`--attempt final-xcode26`），两份回执都列入 evidence_paths；无法取得 Xcode 26 环境时，在 notes 写明「玻璃分支未编译验证」，T19 仍可 completed，但 T20 中「macOS 26 上的设置窗」行保持 manual-pending，交用户裁决。

**步骤 3：失败归属**

- 失败断言属于本计划新增 selfCheck 或本次改动引起的既有断言回归：回到承担该写集的任务（按 index scopes 查归属）修复，修复后以新 attempt 名重跑步骤 2，旧失败回执保留不覆盖。
- 疑似既有失败：在 T00 记录的实际来源基线（T00.commit）上运行同一命令比较；在已授权的隔离基线比较，不 stash / reset 来源工作区。证实既有失败后保存比较原件，交用户裁决是否不阻塞。
- 用户已明确裁定不阻塞时，按 plan-format「回执与交付映射」记录 failure-disposition（来源必须是 T00 的实际来源）；`T19.tests` 写实际结果及处置引用，不写 pass。
- fix/code-audit 若在执行期间合入 main 并被并入实施分支，先按 index「与 fix/code-audit 的衔接」重跑一次再进入本步。

**步骤 4：保存 completed**

- `node "${CLAUDE_PLUGIN_ROOT}/scripts/execution-evidence.mjs" verify --feature "<实施路径>/.spec-dev/2026-10-29-01-settings-ui-redesign" --record <步骤 2 返回的 record 路径> --candidate <待验 SHA>`，确认回执适用于当前候选。
- 临时文件 + rename 写 `T19 = { status: completed, commit: <待验 SHA>, tests: pass, evidence_paths: [<record 路径>…] }`、`current: null`；`git add -- .spec-dev/2026-10-29-01-settings-ui-redesign/plan/progress.yaml && git commit -m "chore(T19): 记录 final 验证"`。
- 随后进入独立审查（executing-plans 的审查环节），再进入 T20。

**收尾**：后续审查、验收或合并检查引出修复时，回到承担写集合的任务补验，再以新 attempt 重跑本票步骤 2–4；旧 completed 不使新候选自动放行。

**风险**：
- `--self-test` 只覆盖纯函数与既有引擎断言，视觉改动全部依赖 T20 的人工与截图；F 通过不代表视觉验收通过。
- Xcode 26 环境可能不可得（D4），此时玻璃分支只经过 `#if compiler(>=6.2)` 的语法隔离，未经真实编译；首次在新 SDK 编译可能暴露 `glassEffect` 签名差异，修复归 T01。
- `SelfTest` 串行执行，任一新断言崩溃（而非 FAIL）会让后续断言不运行；看到进程异常退出时按崩溃处理，不按单条失败处理。
